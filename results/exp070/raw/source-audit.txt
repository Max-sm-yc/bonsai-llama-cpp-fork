Normal CLI path
---------------

tools/cli/main.cpp:3-4 delegates to llama_cli(). tools/cli/cli.cpp:58-64
creates cli_context and enters its loop. tools/cli/cli-context.cpp:121-132
starts an embedded server before prompting; later user messages become
/v1/chat/completions requests (350-365, 478-497). Server initialization in
tools/server/server-context.cpp:1060 creates the model/context before later
requests are accepted. Therefore llama-cli cannot choose n_ubatch from a
future arbitrary request's token count in its generic server-backed path.

Direct one-shot path
--------------------

examples/simple/simple.cpp:89-107 loads the model and vocab and tokenizes its
single command-line prompt before context creation at 111-119. It could select
a requested ubatch using n_prompt. The sample's default batch is n_prompt, so
effective n_ubatch is additionally clamped to min(n_batch, n_ctx). A temporary
opt-in was implemented in this file, built, and exercised, then reverted after
the decode gate failed. The temporary rule was n_prompt >= 1536 -> request
2048; otherwise request 512. No benchmark ID or prompt string was inspected.

Runtime setting semantics
-------------------------

common/common.cpp:1290-1402 creates context params before llama_init_from_model;
common/common.cpp:1716-1738 copies params.n_ubatch into context params.
src/llama-context.cpp:334-337 clamps the micro-batch to min(n_batch, n_ubatch)
while constructing the context. The server reads llama_n_ubatch(ctx_tgt) later
in request processing (tools/server/server-context.cpp:3025-3027). There is no
per-request n_ubatch setter for the shared server context.
