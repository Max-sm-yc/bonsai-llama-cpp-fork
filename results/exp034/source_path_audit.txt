No source edits were made. A persistent sidecar cache local to mmvq would not have a safe cleanup notification from the CUDA buffer destructor and could retain a stale key after allocation reuse. Conversion into a per-call temporary would incur repeated full-tensor repacking and an approximately 19 MiB temporary per selected matrix invocation; doing this for all rows in the active GEMV would add conversion work to every decode token. A safe persistent implementation requires passing the owner buffer context/registration through the op dispatch and attaching sidecar ownership to that context so free_buffer releases it. This was not prototyped because it crosses CUDA buffer lifetime and operation dispatch, beyond a GEMV-local experiment.
